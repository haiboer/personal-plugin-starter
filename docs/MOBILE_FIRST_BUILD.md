# App 优先的插件构建与验收 v1

插件只维护一份业务源码。Shell 审核固定入口及全部资源，将其构建时集成进同一 App；网页、Android、iOS 共用业务模型和后端契约。`standalone-dist/` 是开发预览或独立产品产物，不是 Shell 动态安装入口。目标手机 App 优先，平板和桌面仍须分别适配。

## 固定交付步骤

```bash
npm ci
npm run typecheck
npm run test
npm run build:plugin
npm run build:standalone
npm run check:manifest
npm run check:consistency
npm run check:package
```

`build:plugin` 生成 `dist/shell-entry.js`、样式／相对分块和按路径排序的 `dist/SHA256SUMS`。校验器要求清单入口、每个摘要与目录内**恰好**相同的一组文件；改动、漏文件、额外文件或清单顺序错误均拒绝。提交源码提交号、清单、完整 `dist/`、清单自身摘要和测试记录。安装方再从实际交付包运行相同校验，不只比对入口文件。

清单 `schemaVersion`、插件 ID、版本、`entry.shell`、后台 origin／受众、能力和数据申报须与运行时及审核记录一致。Shell 当前只安装受控构建，不会从插件仓库或远程 URL 自行拉取代码。更改发布版本、权限或原生能力应重新审核、重新构建 App，保留上一受审包及回滚方案。

## 手机优先的接口约定

- Shell 绘制唯一顶栏并提供详情标题／返回；插件只绘制业务区。页面根节点服从宿主容器高度和安全区，不再叠加 `100vh` 顶栏。业务按钮留在内容区。
- 托管身份从可选 `context.identity.getHostedAccessToken(signal)` 获取插件专用短期凭证。Shell 负责网页 Cookie 与原生安全存储会话；插件不读取平台主令牌或自选发布 ID。`src/host-identity.ts` 在账号变化、退出和停用时中止请求，后台仍须验签、在线复核与按资源授权。
- 原生能力通过 Shell 已审核接口申请。清单声明只是审核输入，不能自动得到相机、相册、通知或局域网许可；系统用途说明、平台实现和真机验收要随具体能力提交。本模板不内置这些权限。

## 验收矩阵

| 场景 | 手机 App 必查 | 平板／桌面补查 |
| --- | --- | --- |
| 导航与布局 | 390px 级宽度、触控、安全区、输入法、滚动、详情返回、关闭、单顶栏 | 768px 与宽屏的布局、键盘和鼠标 |
| 身份 | 登录、退出、换号、撤权、后台恢复、迟到响应不串号 | 多标签页和刷新后的同一权限结果 |
| 网络与数据 | 弱网、断网恢复、401/403/503、上传下载、长请求中止、A/B 数据隔离 | 相同业务结果与可读布局 |
| 系统权限 | 用户主动触发、拒绝、设置中恢复、功能不可用提示 | 网页无原生能力时的降级 |

模板本地预览只验证页面与代码，不代替 Android/iOS 安装包、真机权限弹窗、实际网络及性能验收。交付报告逐项写“通过／失败／未测”，不得把模拟器或 API 200 写成真机通过。Capacitor 的 `sync` 将已构建网页资源复制到原生工程；实际安装包的签名、系统权限和设备兼容性由 Shell 构建流程负责。
